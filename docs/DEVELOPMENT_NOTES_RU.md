# BrotherFastPrint 0.3.2 Preview

Системная Android PrintService для Brother HL-L2340DWR / HL-L2340DW series. PDF обрабатывается на телефоне: полосный PdfRenderer → монохромный растр → JNI/brlaser → одно RAW TCP-задание. ПК, CUPS-сервер и интернет для печати не нужны.

На 1 ноября 2026 года пользователь подтвердил работу плагина после исправлений 0.3.2. Ранее подтверждены физическая печать POC, быстрая многостраничная печать, поиск IP/RAW-порта и long-edge duplex. Это пользовательская аппаратная проверка, а не количественный benchmark; short edge, landscape и 50 страниц на телефоне остаются отдельными проверками.

## Установка

1. Установите `BrotherFastPrint-0.3.2-preview-arm64.apk`. Это отдельное тестовое приложение **BrotherFastPrint Preview**, package `ru.brotherfastprint.preview`. Поверх 0.3.0/0.3.1 Preview устанавливается как обновление с сохранением настроек и прежней подписью. Рабочую 0.2.1 удалять не требуется. Старый ключ подписи не сохранился после очистки среды, поэтому установка поверх неё невозможна. Настройки предыдущего приложения автоматически не переносятся.
2. Откройте Preview. Телефон и принтер должны находиться в одной локальной сети. Нажмите **«Поиск»**; выберите найденный принтер — IP и проверенный RAW-порт сохранятся вместе. Либо нажмите на строку адреса и задайте `192.168.1.41:9100` вручную. Кнопка **«Проверить»** проверяет TCP без отправки задания.
3. Нажмите **«Настройки печати Android»** и включите **BrotherFastPrint Preview**. Временно выключите старую BrotherFastPrint, чтобы не путать две службы. Никакое приложение удалять не нужно.
4. В другом приложении откройте стандартную функцию **«Печать»**, выберите **Brother HL-L2340DWR · FastPrint**. A4 / 600 DPI / monochrome; копии, диапазон, ориентация и duplex выбираются в системном диалоге. Системная печать работает без постоянно открытого экрана Preview; пользователь подтвердил результат 0.3.2.

Если приложение не предоставляет Android-печать, плагин не может добавить эту функцию в его меню. В Preview меню **⋮ → Печать PDF напрямую** позволяет выбрать PDF системным файловым диалогом. Печать начинается после подтверждения. Для диагностики: **⋮ → Тестовая страница** (1 или 4 страницы) и **⋮ → Диагностика** (просмотр, копирование и «Сохранить лог» в TXT через системное окно).

## Интерфейс и настройки

Выбран компактный вариант: карточка принтера с адресом и доступностью, «Проверить» / «Поиск», duplex, экономия тонера и переход в системные настройки. Текущее задание и отмена появляются во время работы. Поддерживаются светлая и тёмная тема, системные/клавиатурные отступы и ограничение ширины контента на складном экране.

Настройка «Двусторонняя печать» задаёт значение по умолчанию: **односторонняя**, **длинный край**, **короткий край**. Оба duplex-режима объявлены в Android capabilities и передаются на каждое задание. Выбор в системном диалоге имеет приоритет над настройкой приложения. После смены значения при необходимости заново откройте диалог печати.

brlaser формирует duplex-команду `ESC&l2S`; для long edge приложение дополнительно разворачивает растр оборота на 180° и меняет верхнее/нижнее поле, как cups-filters для `cupsBackSide=Rotated`. Для short edge оборот не разворачивается. Перед следующей копией нечётного документа добавляется пустой оборот; последняя копия также завершается целым листом. Физическое направление переворота надо проверить на асимметричном тесте с метками TOP/BOTTOM, включая landscape.

## Поиск принтера

По кнопке запускается ограниченный 15 секундами mDNS / DNS-SD поиск `_pdl-datastream._tcp`, `_ipp._tcp`, `_ipps._tcp`, `_printer._tcp`. Выбираются объявления HL-L2340D series по имени/TXT; неизвестные модели не добавляются только из-за открытого порта.

- Для RAW-объявления сохраняется объявленный порт, даже если он отличается от 9100.
- Для IPP/IPPS/LPR используется найденный IP, затем **отдельно проверяется RAW 9100**. IPP 631, IPPS и LPR 515 не получают поток HBP.
- Каждый результат проверяется TCP-подключением без печатных байтов. Поиск не сканирует всю подсеть.
- Android 13+ использует NSD по физическим Wi-Fi/Ethernet сетям; Android 14+ — ServiceInfoCallback с адресами. На Android 8–12 старое разрешение адреса выполняется последовательно, multicast lock освобождается после поиска.
- Закрытие диалога/Activity останавливает поиск и освобождает callbacks, сокеты и multicast lock. Отключённый mDNS не мешает печатать по сохранённому ручному адресу.

Маршрутизатор/принтер должен публиковать DNS-SD и пропускать multicast. Автоматическое обнаружение не обещается при изоляции Wi-Fi-клиентов или блокировке multicast VPN-клиентом; ручной адрес остаётся доступен.

## Доступность после закрытия приложения

Системная служба и discovery принадлежат Android и не используют Activity как условие работы. При новом процессе ручная запись публикуется сразу с состоянием «проверка доступности». В 0.2.1 любой провал короткой TCP-проверки делал запись недоступной, включая timeout/запрет фоновой сети. В 0.3 только явный отказ RAW-порта (`REFUSED`) даёт OFFLINE. Timeout, смена маршрута, фоновые/VPN-ограничения дают UNKNOWN с возможностью выбрать сохранённый принтер; результат фактического задания сообщается отдельно.

При `onDisconnected` прекращаются probes и сетевые callbacks; после повторного подключения они восстанавливаются для активного discovery/tracking. События lifecycle, сети и probe записываются в ограниченный приватный журнал и доступны после нового процесса. Содержимое, названия и URI документов туда не записываются. Это исправляет обнаруженные ограничения кода, но без лога исходной неисправности не доказывает конкретную причину поведения Samsung. Проверка на телефоне обязательна.

Смахивание приложения из недавних и **«Принудительно остановить»** — разные действия. После Force Stop следует снова открыть приложение: Android блокирует остановленный пакет. Постоянный foreground-service, boot-receiver и дополнительные запросы исключений из экономии батареи не добавлены.

## Системный старт 0.3.2

По логу 0.3.1 служба и RAW-проверки работали в фоне с VPN. Задание поступило в engine почти одновременно с открытием Activity, затем полностью подготовилось и передалось за 2240 мс. `queued_ms=0` относится только к внутренней очереди engine, а не ко времени ожидания Android. Во втором сценарии «Принтер не готов» нового job_received не было: документ ещё не передавался плагину. Точную причину барьера на телефоне исходный лог не устанавливает.

Изменения 0.3.2:

- Полный PrinterInfo с A4/600/mono/duplex помещается в session cache **в конструкторе**, до подключения observer и до сетевых запросов. Android может сразу получить готовую ручную запись без ожидания Activity/первого TCP probe.
- ServiceDispatcher создаёт async main Handler, как framework PrintService. Service, engine, discovery, NSD, диагностика и callback binding PDF-процесса (API 29+) не ждут UI sync barriers. Main-thread контракт PrintService соблюдается; это не перенос framework API на worker.
- PrinterPublisher проверяет реальный cache после addPrinters. Если framework удержал старый PrinterInfo вне активного discovery, кеш обновляется buffered remove/add с тем же PrinterId. На реализациях, где обновление уже работает, remove/add не выполняется.
- Пока Android запрашивает discovery/tracking или есть активное задание, служба дополнительно проверяет системную очередь раз в 5 секунд. После отключения/простоя проверки прекращаются. Подхвату подлежат только QUEUED, ещё не управляемые живой записью; STARTED/BLOCKED не печатаются повторно. После восстановления неизвестное начатое задание завершается FAIL_UNCERTAIN.
- В журнал добавлены instance/session, начальная публикация capabilities/status, фактический callback задания, источник принятия callback/queue_scan и запоздание main-dispatch. document_age_ms включает время в preview и не выдаётся за время в очереди.

Новых permissions, постоянно работающего foreground-service, wakelock и автоматических изменений VPN/батареи нет. Код устраняет обнаруженные уязвимые места, но не объявляет конкретный UI barrier или политику Samsung доказанной причиной. После обновления пользователь подтвердил, что плагин работает как требовалось. Это не устанавливает точную первопричину прежней задержки.

## Постоянная диагностика 0.3.1

В 0.3.0 на диск попадали только события службы; подробный лог задания оставался в памяти. Теперь render/mono/encode/TCP/job_end и probes также записываются в общий ограниченный журнал. Каждое событие получает UTC и идентификатор процесса/сессии; конец задания синхронизируется с диском на worker с ограниченным ожиданием. Лог не создаёт новые задания и не включает документ в отчёт.

«Сохранить лог» открывает системный выбор места для TXT. Разрешение на все файлы не нужно; приложение пишет только в выбранный пользователем файл. Выгрузка выполняется явно, автоматической отправки разработчику или в облако нет. Внешний TXT остаётся в выбранном месте после удаления приложения.

Отчёт включает app/API/model, текущий адрес/порт, duplex, историю событий и техническую сводку Java crash (класс, методы и номера строк). Сообщения Throwable и filenames исключены, поскольку могут содержать названия/URI документов. Crash handler передаёт управление стандартному обработчику Android, не перезапускает приложение и не повторяет печать. Он устанавливается только в основном UID; изолированный PDF-процесс доступа к приватному каталогу не получает.

На Android 11+ добавляются до 8 доступных записей ApplicationExitInfo только собственного пакета: время, reason/status, PID, importance и PSS/RSS. Description, traceInputStream, tombstone/ANR trace и processStateSummary не читаются. На старых Android явно отмечается отсутствие этого API. Наличие записей зависит от ОС; по отсутствующей записи нельзя объявлять причину завершения.

Очередь журнала ограничена, переполнение отмечается `journal_dropped_events`; ошибка записи — `journal_write_error`, она не отменяет печать. Ротация сохраняет только последние события, а мгновенный SIGKILL/отключение питания может прервать сохранение последних строк. Это диагностическая информация, не доказательство физической печати и не резервная копия документов.

## Обработка, сеть и ограничения

Сначала весь документ с выбранными страницами и копиями готовится во внутренний файл. После этого открывается одно TCP-соединение и передаётся один HBP job с единственным JOB/EOJ. Рендер между отправляемыми страницами уже не выполняется. Streaming пока не реализован: preload сохраняет подтверждённую пользователем быструю печать, а сравнение режимов требует измерения на принтере.

Bitmap — полоса 4827×128 ARGB (около 2,36 MiB), один переиспользуемый монохромный файл около 3,93 MiB. PdfRenderer и JNI работают в изолированном процессе с тремя переданными файловыми дескрипторами. Память приложения не растёт пропорционально количеству страниц; сложный PDF дополнительно расходует память самого PdfRenderer.

Лимиты: PDF 256 MiB, HBP 512 MiB с резервом диска 64 MiB, 500 выходных сторон с учётом копий и пустых оборотов, до 99 копий. Бумага/разрешение в этой версии фиксированы: A4 / 600 DPI / monochrome. Диапазоны Android используются относительно фактического spool PDF; копии разбираются по экземплярам. Временные файлы приватные, удаляются после попытки и очищаются после аварийного завершения при следующем запуске.

Connect timeout 5 сек; допустимы две попытки только до отправки печатных байтов. Write idle timeout 15 сек, общий предел передачи 10 минут. После начала записи повтор на другом маршруте или автоматическая повторная печать запрещены. Прерванный процесс не восстанавливает отправку старого job. RAW-успех означает передачу сетевому стеку, а не подтверждение физического выхода бумаги. Отмена не может забрать данные, уже полученные принтером.

Без VPN используется прямой Wi-Fi/Ethernet. При VPN сначала системный маршрут, учитывающий разрешённый VPN-клиентом LAN-обход, затем допустимый физический маршрут. Cellular-only не выбирается. Адреса ограничены числовыми частными/link-local IPv4; документы в интернет/API не отправляются. Если VPN запрещает оба маршрута, его правила нельзя отменить из приложения.

## Конфиденциальность и разрешения

Нет аналитики, облачной обработки, входящего HTTP/TCP-сервера или стороннего API. Backup документов и настроек отключён. Технический журнал содержит только параметры/события; два файла максимум по 128 KiB, без содержимого PDF. Отдельно хранится ограниченная сводка последнего Java crash без exception messages и имён исходных файлов. Поиск адресов использует системный NSD.

Разрешения: INTERNET, ACCESS_NETWORK_STATE, CHANGE_NETWORK_STATE, CHANGE_WIFI_MULTICAST_STATE. Последнее нужно для multicast lock на Android до 13. Для targetSdk 36 нет включённого opt-in ограничения локальной сети; runtime-диалоги location/storage не нужны. Контакты, все файлы устройства, местоположение, камера и микрофон не запрашиваются.

## Сборка

Версии инструментов закреплены, побитная идентичность разных окружений отдельно не проверена. Debug-подпись тестовая; приватный ключ не входит в архив исходников.

Откройте проект в Android Studio, установите указанные инструменты, задайте путь SDK через Android Studio либо `local.properties`. Интернет нужен для загрузки инструментов и зависимостей, не для работы приложения.

```bash
./gradlew --no-daemon :app:assembleDebug :app:assembleDebugAndroidTest :app:testDebugUnitTest :app:lintDebug
bash tools/test_native.sh
```

APK: `app/build/outputs/apk/debug/app-debug.apk`. Host-тестам нужны C++17 и Python 3. `./gradlew :app:connectedDebugAndroidTest` выполняет отдельные device-тесты PdfRenderer/Binder/JNI и manifest без печати на принтере. В текущем окружении они только собраны, не запущены. `.github/workflows/build.yml` подготовлен для будущего репозитория; на GitHub не запускался.

## Что требуется проверить на Samsung

1. «Поиск» находит HL-L2340DWR; после выбора сохраняются правильные IP и RAW-порт, «Проверить» проходит.
2. Длинный и короткий край в системном диалоге: 4 страницы, TOP/BOTTOM, номера, порядок, поля; затем landscape. Отдельно нечётный диапазон и две копии: экземпляры не должны попадать на один лист.
3. Смахнуть Preview из недавних; открыть печать из Word/PDF без запуска Preview. Принтер выбирается, job печатается. Повторить с VPN.
4. При сбое открыть **⋮ → Диагностика → Сохранить лог** и прислать TXT-файл вместе с видом закрытия/VPN-клиентом. События предыдущего процесса сохраняются.
5. Сравнить одинаковый 10-страничный PDF со стандартной службой и iPrint&Scan; время выхода листов измеряется отдельно, а не по `tcp_end`.
